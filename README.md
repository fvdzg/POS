# POS# ПОС — Преподавательская Оценка Студентов

Консольный модуль учёта преподавательской оценки студентов.
Реализован на C# с применением DDD, архитектуры Ports and Adapters и паттернов GoF.

## Запуск

Нужен .NET SDK 10 (в проектах указан `net10.0`).

```
dotnet build
dotnet test
dotnet run --project src/POS.Cli
dotnet run --project src/POS.Cli -- --demo
```

- Без аргументов программа предлагает запустить демо-сценарий, затем открывает интерактивное меню.
- С флагом `--demo` выполняется только демо.
- Данные меню хранятся в папке `data` рядом с исполняемым файлом (`src/POS.Cli/bin/Debug/net10.0/data`),
  данные демо — в отдельной папке `data-demo`, которая пересоздаётся при каждом запуске демо.

## Что умеет приложение

- Студенты: добавить (ФИО и группа), показать список, удалить (вместе с его оценками).
- Рубрикатор: добавить критерий (название, максимальный балл, вес), показать список,
  удалить критерий (только если по нему нет оценок).
- Оценки: выставить, исправить (повторная выставка по тому же критерию), отменить, посмотреть оценки студента.
- Итог: по одному студенту и по всем, в двух режимах расчёта.
- Экспорт итогов в `.csv` или `.json` (формат выбирается по расширению файла).
- Демо-сценарий: завести критерии и студентов, выставить оценки, показать отклонение нарушений правил,
  исправить оценку, посчитать итоги по группам в двух режимах, выгрузить итог.

## Предметная область

| Термин | Класс в коде | Смысл |
|---|---|---|
| Студент | `Student` | тот, кого оценивают |
| Рубрикатор | `Rubric` | набор критериев курса |
| Критерий | `Criterion` | за что ставят балл: название, максимум, вес |
| Оценка | `Evaluation` | факт «по этому критерию поставили такой балл», комментарий и время |
| Ведомость | `EvaluationSheet` | все оценки одного студента |
| Итог | `FinalResult` | результат по студенту, вычисленный из оценок и рубрикатора |

Правила, которые модель не позволяет нарушить:

1. Балл лежит в диапазоне `[0; max]` критерия (`ScoreOutOfRangeException`).
2. Оценку можно выставить только по критерию из рубрикатора (`CriterionNotFoundException`).
3. Итог согласован с текущим набором оценок: он не хранится, а считается Domain Service
   `FinalResultCalculator` при каждом запросе.
4. Дополнительно: название критерия уникально в рубрикаторе, `max > 0`, `вес > 0`,
   по критерию не больше одной оценки у студента.

Итог считается в процентах: `Σ(вес · балл / max) / Σ(вес) · 100`. Веса относительные,
их сумма не обязана равняться единице. Также показывается итог по десятибалльной шкале (процент / 10).

## Архитектура: Ports and Adapters

```
Pos.Cli  ──────────►  Pos.Application  ──────►  Pos.Domain
(меню, демо,            (сценарии, DTO,            (сущности, VO,
 composition root)       Facade, порты              инварианты,
      │                  выгрузки)                  Domain Service,
      │                      ▲                      порты-репозитории)
      ▼                      │
Pos.Infrastructure ──────────┘
(JSON-репозитории, экспорт CSV/JSON)
```

Зависимости направлены внутрь: Domain не ссылается ни на что, Application знает только Domain,
Infrastructure реализует порты, объявленные в Domain и Application. Конкретные классы связывает
только `CompositionRoot` в проекте `Pos.Cli`.

| Проект | Роль | Что внутри |
|---|---|---|
| `Pos.Domain` | ядро | сущности, Value Object, инварианты, фабрика оценок, стратегии итога, Domain Service, интерфейсы репозиториев |
| `Pos.Application` | сценарии | `StudentUseCases`, `CriterionUseCases`, `EvaluationUseCases`, `ResultUseCases`, `PosFacade`, DTO, порт `IResultExporter`, `ScoringStrategyRegistry` |
| `Pos.Infrastructure` | вторичные адаптеры | JSON-репозитории, `CsvResultExporter`, `JsonResultExporter` |
| `Pos.Cli` | первичный адаптер и сборка | меню, демо, DI-контейнер |
| `Pos.Tests` | тесты | инварианты, Domain Service, сценарии, хранилище, выгрузка |

## Карта DDD

- **Ubiquitous Language.** Названия классов и методов повторяют язык заказчика: студент, критерий,
  рубрикатор, оценка, ведомость, итог, выставить, исправить, отменить.
- **Entity.** `Student`, `Rubric`, `Criterion`, `EvaluationSheet`: у них есть идентичность (`StudentId`, `RubricId`,
  `CriterionId`), равенство определяется идентификатором. Два студента с одним `StudentId` равны,
  даже если ФИО различаются.
- **Value Object.** `Evaluation`, `FinalResult`, `Weight`, `Score` и идентификаторы: неизменяемы,
  равны по значению. Оценку не «редактируют», а заменяют новой: исправление в `EvaluationSheet.Assign`
  подменяет значение целиком.
- **Агрегаты.** `Rubric` (корень) содержит `Criterion`: критерии меняются только через рубрикатор,
  поэтому он охраняет уникальность названий. `EvaluationSheet` (корень, идентичность — `StudentId`)
  содержит оценки студента и охраняет правило «одна оценка на критерий». Агрегаты ссылаются
  друг на друга по идентификаторам.
- **Инварианты** охраняются там, где живут данные: диапазон баллов и принадлежность рубрикатору —
  в `Criterion.EnsureAllows` и `EvaluationFactory`; уникальность критериев — в `Rubric`;
  уникальность оценки по критерию — в `EvaluationSheet`. Конструкторы `Evaluation` и `FinalResult`
  закрыты (`internal`), создать их в обход проверок нельзя.
- **Repository (порт).** `IStudentRepository`, `IRubricRepository`, `IEvaluationSheetRepository` объявлены в Domain,
  реализованы в Infrastructure.
- **Domain Service.** `FinalResultCalculator`: расчёт итога не принадлежит ни рубрикатору, ни ведомости,
  ему нужны оба. Он также проверяет, что в ведомости нет оценок по критериям, которых нет в рубрикаторе.

## Паттерны GoF

| Группа | Паттерн | Где | Какую боль закрывает |
|---|---|---|---|
| Порождающий | Фабрика | `EvaluationFactory` | единственная точка создания оценки: проверка рубрикатора и диапазона баллов в одном месте. Через неё проходит и загрузка оценок из JSON, поэтому испорченный файл не нарушит инварианты |
| Структурный | Декоратор | `RoundingFinalScoreDecorator` поверх стратегий | округление не дублируется в каждой стратегии; новые модификаторы итога (бонус, штраф) добавляются обёрткой, без правки существующих классов. Цепочка собирается в `CompositionRoot` |
| Структурный | Фасад | `PosFacade` | консоль зависит от одного объекта вместо четырёх групп сценариев и не знает репозиториев |
| Поведенческий | Стратегия | `IFinalScoreStrategy`: `StrictWeightedScoreStrategy`, `RatedOnlyWeightedScoreStrategy` | сменяемое правило итога: «строгий» (неоценённый критерий = 0) и «только по оценённым». Режим выбирает пользователь, `ScoringStrategyRegistry` отдаёт нужную стратегию |


## DI-контейнер

`Microsoft.Extensions.DependencyInjection`. Граф собирается в `src/POS.Cli/CompositionRoot.cs`:
репозитории регистрируются под интерфейсами, экспортёры — как `IEnumerable<IResultExporter>`,
цепочки «округление поверх стратегии» собираются в `ScoringStrategyRegistry`. Время берётся через
встроенный `TimeProvider`, поэтому в тестах его можно подменить.

## Тесты

`dotnet test`. Покрыто:

- инварианты домена (диапазон баллов, рубрикатор, уникальность, веса);
- расчёт итога обеими стратегиями и декоратором;

- экспорт CSV и JSON.

## Допущения и ограничения

- В модуле один рубрикатор (один курс). Порт `IRubricRepository` рассчитан на расширение до нескольких курсов.
- Критерий нельзя удалить, пока по нему есть оценки. Значения критерия (максимум, вес) не редактируются:
  изменение максимума задним числом сломало бы уже выставленные оценки.
- Удаление студента удаляет и его ведомость (на уровне сценария).
- Хранилище — JSON-файлы, без блокировок: приложение рассчитано на одного пользователя.

## Как расширять

- Пересдачи и апелляции: новые операции в `EvaluationSheet` и новые значения в `Evaluation` без изменений рубрикатора.
- Несколько курсов: идентификатор курса в `Rubric` и поиск рубрикатора по нему в репозитории.
- Новое правило итога: ещё одна реализация `IFinalScoreStrategy`, регистрация в `CompositionRoot`.
- Новый формат выгрузки: ещё одна реализация `IResultExporter`.
